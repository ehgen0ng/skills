# 测试临时资源管理

测试、调试、迭代验证和 Spec 收尾都遵守本规则。仅为当前验证或排障而生成、下载、解压或安装的资源，按需使用，放在仓库外的系统临时目录，用完主动清理。

## 资源边界

| 类型 | 处理方式 |
|------|----------|
| 测试产生的数据 | 截图、录屏、日志、覆盖率、诊断文件、临时数据库等按需生成，提取结论后清理 |
| 测试临时引入的环境 | 运行时、工具、SDK、浏览器、模拟器、系统镜像及安装包等优先复用已有环境，缺少时临时准备 |
| 工具附带的可写数据 | 下载/包缓存、用户配置、浏览器 profile、虚拟设备磁盘、快照、临时服务数据与工具一并纳入临时目录和清理范围 |
| 项目长期资产 | 源码、声明的项目依赖及锁文件、必要夹具、人工维护的回归基线、测试计划和结论按项目规范维护，不作为临时资源清理 |

这些类别按用途判断，不依赖某个语言、工具名称或文件扩展名。新增项目长期依赖与本次验证临时借用工具应分开处理。

## 采集范围

- Spec 长期保留测试计划、测试报告、问题诊断与修复结论；测试代码、必要的固定夹具和人工维护的回归基线仍属于项目源码。
- 截图、测试 ZIP、trace、录屏、原始覆盖率、事件日志、诊断转储、构建日志、自动生成的 HTML/JSON 报告和临时测试数据都是运行产物，不写入仓库或 Spec，不提交 Git。
- 不通过 `.gitignore` 忽略测试产物，也不把已有忽略规则当作允许它们留在项目内的理由；应配置到系统临时目录并及时清理。这不限制其他用途的 `.gitignore` 正常维护。
- 只采集验收断言或当前排障需要的证据。截图按关键断言或失败现场采集；trace/录屏按复现需要启用，不默认全程录制、打包或保存所有轮次。
- 覆盖率仅在测试计划或本次验证需要时开启。`v8-raw/`、`v8-coverage.json`、`coverage-raw.ndjson` 等原始数据只临时用于计算汇总，提取必要指标后清理；仍需排障的数据按下方生命周期处理。

## 输出位置

1. 运行前通过当前平台的系统临时目录 API 分配本任务专属目录，路径包含项目、Spec、run 的可识别信息及随机后缀。将实际绝对路径记为 `TEST_TMP_ROOT`；按需使用其中的 `tools/`、`cache/`、`data/`、`artifacts/`，产物目录记为 `ARTIFACT_DIR`。
2. 检查解析后的真实路径位于仓库之外；环境变量指定的临时根目录若落在仓库内，改用仓库外可写的系统临时目录。不要在项目内创建缓存目录，也不要从 Spec 建立指向产物的符号链接。
3. 显式把测试工具的输出目录、截图/视频/trace 路径、覆盖率目录、reporter 输出和日志重定向配置到 `ARTIFACT_DIR`，工具及其缓存、配置和临时数据放入 `TEST_TMP_ROOT`。这两个名称只是本流程的路径约定，设置同名环境变量不会自动重定向所有工具。
4. 运行前确认实际配置，运行后检查是否有工具仍向仓库写入默认产物。不能重定向时先调整测试配置或执行方式；若仍受限，记录阻塞，不能退回 Spec 内积累数据。
5. 不依赖系统缓存目录长期保存证据，也不假定临时目录会在重启时清空；系统清理时机不确定，流程负责主动清理。

证据由测试脚本、测试工具或日志采集命令自动生成，并在采集时脱敏。Agent 可以编写采集逻辑、总结结论，不能手写或补写原始证据。

## 临时工具与跨平台执行

- 先检查当前系统及架构、已有工具的版本与可用性。满足测试要求就复用，不重复安装；不要卸载或清理原本存在的环境。
- 缺少工具时，按当前平台选择可信来源的兼容版本和可移除的解压版、便携版或隔离安装方式，下载包、解压目录和安装缓存均置于 `TEST_TMP_ROOT`。不为一次验证默认执行系统级安装或全局包安装。
- Windows 使用系统临时目录 API（如 .NET 的 `System.IO.Path.GetTempPath()`），macOS/Linux 使用运行时的系统临时目录 API（如 `tempfile` / `os.tmpdir()`）；用平台路径 API 拼接并正确引用带空格路径，不硬编码 `/tmp`、盘符或只适用于某种 shell 的命令。
- 以绝对可执行文件路径或仅对子进程生效的环境变量启动工具；不永久修改系统/用户 PATH、注册表、shell 配置或全局工具设置，不重定义用户 HOME。运行时定位变量按工具支持方式设置，作用域限本次进程。
- 启动前检查工具是否默认向用户目录或系统其他位置写入下载缓存、SDK 包、浏览器文件、模拟器镜像/磁盘、快照、配置或临时服务数据；使用该工具支持的参数和环境变量显式重定向。仅把安装包放进临时目录不算完成隔离。
- 需要驱动、虚拟化组件、系统服务、管理员权限或只能永久安装的工具，不能假装便携版即可满足要求。优先使用已有兼容环境或可用的隔离执行环境；仍无法满足时说明具体阻塞，在获得所需授权前不扩大系统修改范围。
- “支持多平台”要求按目标平台分别验证并报告结果；未在目标系统运行的测试标记未验证，不把本机结果冒充其他平台结果。远程/CI 执行端同样管理自己的临时工具、缓存和产物。

## 报告与交接

- 在 `tester/test-report.md` 或本次调试/迭代报告中保留：run id、代码版本、执行命令、必要环境信息、目标平台和实际验证范围、退出状态、用例结果、覆盖率汇总（如有）、关键错误摘要和复现步骤；临时工具记录版本、来源与必要启动配置以便重建，不保留整套安装文件。
- 临时资源只作为定位信息：记录 `TEST_TMP_ROOT`、必要的产物路径及状态（临时保留/已清理），保留时写明原因和清理条件。交接时确认接收方能访问；跨机器只传必要证据并约定清理，不复制回 Spec。
- 报告应在临时文件删除后仍能独立解释结论。仅引用路径不算完整报告；不得把完整日志、大段 JSON、base64 图片或二进制附件塞入 Markdown 来变相留存。
- 需要长期保存的回归夹具或视觉基线，应提炼为项目测试目录中的最小、脱敏、确定性输入或基线，不能把整轮运行输出当作夹具。

## 清理时机

- **验证完成**：先提取结论与必要摘要，确认无需排障或后续检查，停止本任务启动的服务、浏览器、模拟器等进程并释放文件占用，再删除本次临时目录（含工具、安装包、缓存和产物）；报告标记为“已清理”。清理失败时记录残留路径与原因，不宣称已清理。
- **失败或中断**：仅临时保留尚需分析的最小证据及继续排障必需的环境，删除重复轮次和无关数据，停止不再使用的本任务进程。在交接中说明保留原因与清理条件；重验通过、排障结束或确认不再需要时清理。
- **恢复任务**：检查报告记录的临时路径；已被系统清理时如实标记，需要证据则重跑，不伪造。仍存在但已无用途的本任务产物应清理。
- **收尾/归档**：核对本次测试、调试和迭代的临时路径，清理已完成用途的资源并更新状态；归档仅移动必要文档，不复制临时工具和数据。
- 清理只针对已确认归属于本任务的文件、目录和进程；不清空整个系统临时目录，不删除源码、固定夹具、回归基线、已有工具环境或其他任务的资源。

## 已有项目迁移

- 启用本规则时检查旧的 `tester/artifacts/`、测试输出目录、原始覆盖率数据及临时下载的工具，先更新配置，停止继续向仓库写入。
- 对确认为无用的生成物，删除本地文件；仍需排障的最小证据移入本任务系统临时目录，并记录清理条件。
- 已被 Git 跟踪的生成物还必须从当前版本移除并纳入清理提交，否则拉取旧版本或 reset 仍可能恢复它们。只取消跟踪而把无用文件留在本地不算完成清理。
- 检查实际删除清单和 Git 差异，保留测试源码、必要夹具、人工维护的基线与报告；不要按图片、ZIP、JSON 等扩展名全仓删除。清理当前版本不等于清除 Git 历史中的大对象。
