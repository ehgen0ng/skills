# 编码风格

- Skill 文件使用 Markdown 格式，遵循 Obsidian Flavored Markdown
- YAML frontmatter 只保留 `name` + `description`
- 每个 Skill 主文件 `SKILL.md` 保持精简，详情放 `references/`
- 变量/占位符使用 `{花括号}` 标记
- 文件和目录命名优先使用中文描述或 kebab-case
- 代码注释默认使用简体中文；第三方 API、协议字段、框架术语保留原文
- 新增/修改函数应在函数头附近说明职责；公共函数、跨模块函数、命令入口和回调入口必须写
- 函数头注释优先说明用途、输入输出、副作用和边界；简单私有函数可只写一句职责
- 复杂逻辑必须补充"为什么这样做"、关键边界、失败处理或兼容性原因
- 避免逐行翻译代码、解释显而易见语句，过期注释必须同步更新或删除
- 只改与当前任务相关的文件，避免无关格式化和元数据 churn
